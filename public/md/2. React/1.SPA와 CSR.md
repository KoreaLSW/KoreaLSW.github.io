# SPA(Single Page Application)와 CSR(Client Side Rendering) 핵심 정리

## 1. SPA (Single Page Application)

- <b>정의</b>: 말 그대로 페이지가 하나뿐인 웹 애플리케이션.
- <b>특징</b>: 초반에 한 번만 페이지를 받아오고, 그 후 새로운 페이지를 전체적으로 받아오지 않음.
- <b>결과</b>: 버튼을 누르거나 페이지가 전환될 때 화면 전체를 새로고침(깜빡임)하지 않고 <b>즉각적으로 반응</b>을 함.

---

## 2. CSR (Client Side Rendering)

- <b>정의</b>: 최초 접속 때 웹사이트 전체 리소스(HTML, CSS, JS)를 한 번에 받아와 브라우저에서 그리는 방식.

### 🔄 동작 (로딩)

1. <b>초기 로딩</b>: 최초 접속 때 웹사이트 전체 리소스(HTML, CSS, JS)를 한 번에 받아옴.
2. <b>화면 갱신</b>: 이후 필요한 데이터(JSON)만 서버에서 받아와 JS(브라우저)가 화면의 일부분을 갈아 끼움.

### ✅ 장점

- <b>서버 부하 감소</b>: 서버에서 HTML 전체를 만들어 보내줄 필요 없이 필요한 데이터만 보내기 때문에 서버의 부담을 줄일 수 있음.
- <b>협업 용이</b>: 프론트엔드와 백엔드 분리로 개발 업무 분업화 및 협업이 용이함.

### ⚠️ 단점

- <b>TTV(Time to View)가 느림</b>: JS 파일 다운로드 및 실행, API 호출이 완료되어야 화면이 보이기 시작하므로 사용자가 콘텐츠를 보기까지 시간이 오래 걸림.
- <b>SEO(검색 엔진 최적화)의 어려움</b>: 검색 엔진 로봇이 접속했을 때, 데이터가 없는 <b>빈 HTML</b>만 보일 수 있음.
- <b>보안에 취약함</b>: 클라이언트 측에서 API 키나 인증 토큰 등이 노출될 수 있으며, 소스 코드가 브라우저에 그대로 노출됨.
- <b>CDN 캐시 활용이 어려움</b>: CDN에 캐시하려면 정적 파일이어야하는데데 동적으로 생성되는 콘텐츠가 많아 CDN에서 HTML을 효과적으로 캐싱하기 어려움.

## 3. CSR 렌더링 순서

> <b>핵심</b>: 서버는 <b>빈 껍데기</b>만 주고, 내용물은 <b>브라우저(JS)</b>가 나중에 채운다.

1. <b>서버 요청 (Request)</b>: 사용자가 사이트 접속.
2. <b>빈 HTML 수신</b>: 서버로부터 비어있는 뼈대 HTML (`<div id="root">`) 수신.
3. <b>JS 다운로드</b>: HTML에 연결된 JS 파일 다운로드.
4. <b>JS 실행</b>: 브라우저가 JS 실행.
5. <b>데이터 요청</b>: JS가 서버 API에 데이터(JSON) 요청.
6. <b>렌더링 (Rendering)</b>: 받아온 데이터를 HTML에 결합하여 화면 표시.

### ⏳ 요약표: 누가 언제 일하나?

| 순서 | 주체            | 하는 일                | 사용자 화면 상태      |
| :--- | :-------------- | :--------------------- | :-------------------- |
| 1    | <b>브라우저</b> | 서버 접속              | 로딩 중               |
| 2    | <b>서버</b>     | 빈 HTML 전달           | ⚪️ 하얀 화면 (Blank) |
| 3    | <b>브라우저</b> | JS 파일 다운로드       | ⚪️ 하얀 화면 (Blank) |
| 4    | <b>브라우저</b> | JS 실행 및 데이터 요청 | ⚪️ 하얀 화면 (Blank) |
| 5    | <b>서버</b>     | 데이터(JSON) 전달      | ⚪️ 하얀 화면 (Blank) |
| 6    | <b>브라우저</b> | 화면 조립 및 표시      | ✨ 완성된 화면        |
