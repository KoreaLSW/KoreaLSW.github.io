# React `useLayoutEffect` 핵심 정리

## 1. 정의 (Definition)

> <b>"브라우저가 화면을 그리기(Paint) 전에, 동기적(Synchronous)으로 실행되는 훅"</b>

- `useEffect`와 사용법은 100% 똑같습니다.
- 하지만 <b>실행되는 타이밍</b>이 다릅니다.
- <b>주 목적:</b> 화면이 깜빡이는 현상(Flicker)을 제거하거나, DOM의 크기/위치를 정확하게 측정할 때 사용합니다.

---

## 2. 핵심 동작 원리: "동기(Blocking) 실행"

### `useEffect`와 `useLayoutEffect`의 비교

#### 🔄 `useEffect` (비동기)

1. 리액트가 DOM을 바꿈.
2. <b>브라우저가 화면을 그림 (Paint).</b> 🎨 (사용자가 변경된 화면을 봄)
3. 그 뒤에 `useEffect`가 실행됨.
4. 만약 여기서 state를 또 바꾸면? 👉 <b>화면이 한 번 더 그려지면서 깜빡임 발생.</b>

#### 🛑 `useLayoutEffect` (동기)

1. 리액트가 DOM을 바꿈.
2. <b>`useLayoutEffect` 실행.</b>
3. 이 안의 작업이 모두 끝난 뒤에야...
4. <b>브라우저가 화면을 그림 (Paint).</b> 🎨
5. <b>결과:</b> 사용자는 깜빡임 없이 최종적으로 완성된 화면만 봄.

---

## 3. 언제 써야 하나요?

대부분의 상황에서는 `useEffect`를 쓰는 것이 좋습니다(성능 때문). 하지만 <b>아래 2가지 상황에서는 `useLayoutEffect`가 필수</b>입니다.

### ① 화면 깜빡임(Flicker) 제거

- State가 바뀌자마자 DOM 스타일을 수정해야 하는데, `useEffect`로 하면 사용자가 <b>스타일이 적용되기 전의 못난 화면</b>을 잠깐 보게 될 때.

### ② DOM 요소의 크기/위치 측정

- 요소가 화면에 나타나기 전에 미리 높이나 넓이(`getBoundingClientRect`)를 재서, 그에 맞춰 레이아웃을 다시 잡아야 할 때.

---

## 4. 코드 예시: 깜빡임 해결하기

<b>상황:</b> 숫자가 0이면 순식간에 랜덤 숫자로 바꿔야 하는 로직.

### ❌ `useEffect` 사용 (깜빡임 O)

```javascript
useEffect(() => {
  if (value === 0) {
    setValue(10 + Math.random() * 200);
  }
}, [value]);
```

> <b>사용자 경험:</b> 화면에 아주 찰나의 순간 `0`이 보였다가(Paint 1), 랜덤 숫자로 바뀜(Paint 2). 눈이 피곤함.

### ✅ `useLayoutEffect` 사용 (깜빡임 X)

```javascript
useLayoutEffect(() => {
  if (value === 0) {
    setValue(10 + Math.random() * 200);
  }
}, [value]);
```

> <b>사용자 경험:</b> 브라우저가 화면을 그리기 전에 가로채서 숫자를 바꿔버림. 사용자는 `0`을 절대 보지 못하고 바로 완성된 랜덤 숫자만 봄.

---

## 5\. ⚡️ useEffect vs useLayoutEffect 비교

| 구분          | useEffect                          | useLayoutEffect                           |
| :------------ | :--------------------------------- | :---------------------------------------- |
| <b>실행 시점</b> | 화면이 그려진 <b>후</b> (Paint After) | 화면이 그려지기 <b>전</b> (Paint Before)     |
| <b>방식</b>      | <b>비동기</b> (기다려주지 않음)       | <b>동기</b> (끝날 때까지 화면 렌더링을 막음) |
| <b>주 용도</b>   | 데이터 통신(API), 이벤트 리스너 등 | DOM 측정, 레이아웃 보정, 깜빡임 방지      |
| <b>성능 영향</b> | 좋음 (화면 렌더링 방해 안 함)      | <b>나쁨</b> (작업이 길어지면 화면이 늦게 뜸) |

> <b>💡 결론 가이드</b>
>
> 1.  일단 \*\*`useEffect`\*\*로 코드를 짠다.
> 2.  실행해봤는데 <b>"어? 화면이 미세하게 깜빡거리네? 위치가 튀네?"</b> 하는 느낌이 든다.
> 3.  그때만 \*\*`useLayoutEffect`\*\*로 바꾼다.
